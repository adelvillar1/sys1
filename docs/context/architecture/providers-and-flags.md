# Providers

`src/sys1/providers.py` owns everything about calling a decision model: a registry of `Provider`
dataclasses (see `types.Provider`), the HTTP core, wire factories, availability probes, and the
enable/disable flag machinery.

## The registry

`REGISTRY` maps provider id → `Provider`. `register()` is the extension point; all built-ins
self-register at import. Two tiers: `tier="core"` (decide, jev, drex, glide, julia, liquid, local,
modernbert — on by default) and `tier="candidate"` (clm, openjev, kev, tev1, laya, decide_1b,
decide_multi — off until named in `providers.enabled`). A candidate that speaks an existing wire
needs zero call code: a config entry + one `register()` call.

## Wire families

Every hosted provider's `classify()` is generated by a wire factory keyed off `Provider.wire`:

- `_openai_wire` — OpenAI-compatible chat-completions with a `classifications` schema (decide, kev,
  tev1, laya).
- `_jev_wire` — TypeSafe `/v1/systemone` with `{state, questions}` (jev, clm, openjev); state is
  truncated to `scan.max_diff_chars`.
- `_drex_wire` — same wire but plain-string `state` bounded by `drex_max_chars` (400K), noul
  criteria under `true`/`false` keys via `Head.to_drex_head()`, usage mapped from
  `input_tokens`/`output_tokens` (drex).
- `_glide_wire` — Drex-style with `glide_max_chars` (100K) as the binding bound; strict validation
  (no per-question `id`); explicit confidence on choice/score (glide).
- `_julia_wire` — Drex-style with `julia_max_chars` (12K) as the binding bound; adds the
  `Idempotency-Key` + `User-Agent` headers this host requires (julia).
- `_liquid_wire` — Drex-style with `liquid_max_chars` (150K) as the binding bound against d1's
  65,536-token prompt cap; the only wire that emits `images` (the OpenJev extension: up to 8
  base64 data-URL or `{content_type, base64}` objects, counted in `telemetry["image_count"]` —
  content never logged) and that records `cost_usd` from the response `cost` (liquid).
- `_gliner_wire` — the fastino-prescribed gliner2 classification API. `classification_schema_spec`
  builds the pure task spec (`single` for choice/noul, `ordinal` for score, `instruction` always
  carries the head's task text). Two serving modes: the load-once classifier server when
  `{pid}_server_url`/`local_server_url` is set (with automatic subprocess fallback on mismatch or
  error, recorded in `telemetry["server_fallback"]`), else a subprocess into `_local_venv_python`
  running `_LOCAL_INLINE`.
- ModernBERT (`_modernbert_classify`, `_MODERNBERT_INLINE`) — sentence-encoder cosine similarity,
  eval/calibration only.

## Images (vision inputs)

Every wire factory, `call_provider`, `classify()`, and `cascade_classify()` accepts an optional
`images` list — passed only by callers whose input is visual. `_liquid_wire` is the emitter: d1 is
the pool's only vision-capable provider (`input_modalities: ["text","image"]`), so images ride in
the body before the state, every question sees all of them, and each question bills them again
(1.5 input tokens per 32×32 patch). Other wires ignore the argument, so naming a text-only provider
in a cascade with `images=` silently drops them — the api docstring tells callers to name liquid
explicitly for visual inputs. The log record carries `image_count` (a count, never content); the
JSONL path never sees the base64 payload.

## HTTP core and retry semantics

`http_post_json` is the only HTTP path: retries on 5xx, 429, network errors, and "warming"-style
provider errors with backoff; other 4xx fail fast. Every attempt writes
`http_status`/`latency_ms`/`retries`/`structured_ok` via `_set_telemetry`, and success fills token
usage via `_fill_usage`.

## Availability and flags

Availability is three orthogonal answers: `enabled_set(cfg)` resolves `providers.enabled` tokens
(`core` | `all`/`*` | `optin`/`candidates` | explicit ids, minus `providers.disabled` which always
wins); `is_configured` is the static endpoint/key/venv check; `is_available` (per provider fn:
`_hosted_available` = key present, `_self_hosted_available` = url + key + `_tcp_open` listener,
`_local_available` = server answering or venv present) means usable right now. `provider_report`
returns the full per-id view (enabled/configured/available/reason/config/meta) for `sys1 doctor`
and the dashboard; `availability_reason` is the human sentence for why a provider is off;
`provider_config_view` never includes key values. `call_provider` enforces the flag and raises with
the fix in the message; `resolve_providers` expands user-facing specs (`both`, `core`, `all`,
`optin`, comma lists).

## Gotchas

- The provider id `decide` means the *hosted* fastino wire; the Decide *model* is what `local` runs.
- `drex`, `glide`, `julia`, and `liquid` inherit the `jev` head set (see `heads_for`); they never
  get their own per-task overrides.
- `_requires_key` defaults localhost endpoints to no-auth; force with `{pid}_requires_key`.
